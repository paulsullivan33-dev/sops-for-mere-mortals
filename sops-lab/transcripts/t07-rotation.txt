# A file sealed for the operator alone (rules as in chapter 5).

$ cat .sops.yaml
creation_rules:
    - age: "age1svvqr3y4rhe0dsypnrm5qa8fwlauav7f9ze5hlgm08kysczr450qmg4zht"

$ sops encrypt -i secrets.yaml

$ grep -c "recipient:" secrets.yaml
1

# A teammate joins: add their key to the rules and run updatekeys.

# First attempt, with no key of a current holder in the

# environment: updatekeys must unwrap the data key to re-wrap it,

# so it refuses. A real trap, recorded as it happened:

$ sops updatekeys -y secrets.yaml 2>&1 | tail -4; true

Recovery failed because no master key was able to decrypt the file. In
order for SOPS to recover the file, at least one key has to be successful,
but none were.

# With the operator's key available, the same command succeeds.

# Only the key wrapping changes; the values are not re-encrypted.

$ SOPS_AGE_KEY_FILE=/home/hatch/workspace/sops-labwork/work/keys/operator.txt sops updatekeys -y secrets.yaml 2>&1 | tail -5
